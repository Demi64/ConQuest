# MVP仕様（最初に作って自分で試す範囲）

最終更新：2026-11-10

## 0. 位置づけ

- `docs/spec-draft.md`（仕様書ドラフト）を前提に、最初に実装する範囲を決めたもの。
- **方針転換（2026-11-10）**：普及・スタンダード化は狙わず、まず作者自身が使うための小規模なOSSとして作る。ドラフト1.5章もこの方針に更新済み（公式ホスト版・課金は取り下げ）。**この文書とドラフトが食い違う場合はこの文書を優先する。**
- MVPの目的：作者が数週間使い、「クエストに束ねる構造」と「AIのフォローアップ」が効くかを確かめる。

## 1. 範囲

### 入れる
- クエスト（通常／デイリー／イベント）、タスク、ジャーナル、Quest Board、ログ、トラッカー
- 報告待ちの表示と、人の手による完了
- 状態：Quest Board／受注中／保留（再開日）／完了／破棄
- 繰り返しの定義、デイリーの生成・締め・繰り越し（繰り越し回数）
- 変更履歴と取り消し（AIの書き込みは即時反映のため必須）
- 提案（やる／やらない／止まっている）と、画面での承認・却下
- 未整理の入力（アプリの入力欄）
- **Googleカレンダー連携**：予定の読み込み・表示、クエスト・タスクへの紐づけ
- MCPサーバー：ドラフト6章の18操作から `set_current_zone` と `convert` を除いた16操作

### 後回し
- オフライン対応（オンライン専用で作り、作り直しなしで後から足せる形にしておく）
- 複数ユーザー・アカウント、国際化、課金、BYOK
- HUDの自由配置・レイアウトの保存と配布（MVPは固定配置。パーツの表示／非表示だけ切り替え可）
- ゾーン、位置情報、端末の検知、必要な環境
- プッシュ通知、ネイティブアプリ（Expo）
- タスク⇔クエストの昇格・降格

## 2. 入力とAIの呼び出し

入力の経路は2つ。どちらからでも入力できる。

1. **Claudeから**：Claudeアプリ（チャット・音声）にカスタムコネクタとしてMCPサーバーをつなぐ。話しかけた内容をClaudeがその場で整理して書き込む。
2. **アプリから**：入力欄の内容を「未整理の入力」として保存し、AIを自動で呼んで整理させる。

### アプリからの入力でAIを呼ぶ方式
- **Claude Code の「スケジュール済みタスク（旧ルーティン）」のAPIトリガー**を使う。サーバーから `POST https://api.anthropic.com/v1/claude_code/routines/{id}/fire` を呼ぶと、クラウドでClaude Codeのセッションが1回起動する。
  - ヘッダー：`Authorization: Bearer <タスク専用トークン>`、`anthropic-beta: experimental-cc-routine-2026-04-01`、`anthropic-version: 2023-06-01`、`Content-Type: application/json`。本文は任意の `{"text": "..."}`。
  - 料金：サブスクリプションの使用量から引かれる（API従量課金ではない）。
  - 回数の上限：1タスクあたり1時間30回。
  - 起動したセッションはコネクタ（このツールのMCPサーバー、Googleカレンダー）を使える。
  - 注意：研究プレビューで、APIは実験的なベータヘッダー付き。仕様が変わる可能性がある。**呼び出し部分は差し替えられる形にする**（将来はClaude APIの直接呼び出しに替えられるように）。
  - `text` は信頼できないデータとして扱われる。入力本文は送らず「未処理の入力があります」程度の合図だけ送り、AIはMCPの `get_overview` で入力を読む。
  - 公式ドキュメント：https://code.claude.com/docs/en/routines
- **まとめて1回呼ぶ**：入力が来たらサーバー側で待ち、30秒ほど新しい入力がなければ1回だけ起動する（ドラフト5章の方式）。
- 起動のきっかけ（MVP）：アプリからの入力、提案の却下、更新ボタン。
- **1日1回の棚卸し**：同じスケジュール済みタスクにスケジュールトリガーも付けて実行する（サーバー側の実装は不要）。
- 画面はAIを待たず、保存済みの最新データを出す。AIが動いている間は「整理中」の印を出す。

## 3. 構成

自分用・オンライン専用なので、ドラフト10章のSupabase・PowerSync・Expoは使わない。

| 役割 | 採用 |
|---|---|
| サーバー（API・MCPサーバー・待ち合わせ・定期処理） | Cloudflare Workers（TypeScript） |
| データベース | Cloudflare D1（SQLite） |
| 30秒待ってからAIを呼ぶ処理 | Durable Objects のアラーム |
| デイリーの締め・カレンダーの取り込み | Workers の Cron Triggers |
| 画面 | Webアプリ（PWA。スマホはホーム画面に追加、PCはブラウザ） |
| MCPの認証 | OAuth（claude.aiのカスタムコネクタが要求するため）。利用者は1人 |
| カレンダー | Google Calendar API（OAuthで読み取りのみ）。サーバーが定期的に写しを取り込む |

- 理由：無料枠で収まる、サーバーの管理が要らない、リモートMCPサーバーの実装例が揃っている。
- データモデルはドラフト3章に従う（ユーザー・ゾーン・HUDレイアウト・端末関連の項目は作らないか空のまま）。IDはUUIDにしておき、後のオフライン対応で作り直さずに済むようにする。
- 時刻の既定はAsia/Tokyo（設定として持たせる）。

## 4. 画面（MVP）

固定配置の1画面＋詳細画面。

- ホーム：入力欄、今日のデイリー、トラッカー（報告待ちを上に、ワンタップで完了）、提案（承認／却下）、今日と近日の予定、「整理中」の印
- ログ（受注中・保留・完了・破棄の一覧と絞り込み）、Quest Board
- クエスト詳細：タスク、ジャーナル、紐づく予定、そのクエストへの提案
- 実行履歴・変更履歴（取り消しボタン）

## 5. 使い始めるまでに人がやること

1. Cloudflareのアカウント作成（済）
2. CloudflareのAPIトークン発行（デプロイ時）
3. スケジュール済みタスクを1つ作り、APIトリガーのトークンを発行してサーバーに登録する
4. claude.aiでカスタムコネクタとしてMCPサーバーを追加する
5. Googleカレンダーの読み取りを許可する（OAuth）

手順の詳細は `docs/setup.md`。実装時に決めた技術的なこと、仕様から変えた点は `docs/design.md`（6章「仕様からの変更・補足」）にまとめた。
